# 工具管理机制深度解析

> AgentJ 项目如何管理 30+ 种工具的核心机制

---

## 📋 核心发现

### 与常见实现的不同

| 常见实现 | AgentJ 实现 |
|---------|-------------|
| 所有工具都是 `@Component` | **大部分工具不是 @Component** |
| Spring 自动扫描注册 | **手动创建并注册** |
| 工具名称固定 | **工具名称带索引后缀** |
| 注册一次，全局使用 | **每次执行动态创建** |

## 1. 工具创建的三种方式

### 方式 1：静态工厂方法（大部分工具）

**为什么用静态方法？**
- 不需要 Spring 管理生命周期
- 工具是无状态的，可以共享实例
- 避免重复创建

**代码示例**：
```java
// DatabaseReadTool 不是 @Component
public class DatabaseReadTool extends AbstractBaseTool<DatabaseRequest> {

    // ❌ 没有 @Component 注解
    // ✅ 提供静态工厂方法
    public static DatabaseReadTool getInstance(
            DataSourceService dataSourceService,
            ObjectMapper objectMapper,
            UnifiedDirectoryManager unifiedDirectoryManager,
            ToolI18nService toolI18nService) {
        return new DatabaseReadTool(
            null,  // lynxeProperties 不需要
            dataSourceService,
            objectMapper,
            unifiedDirectoryManager,
            toolI18nService
        );
    }
}

// PlanningFactory 中使用
toolDefinitions.add(DatabaseReadTool.getInstance(
    dataSourceService,
    objectMapper,
    unifiedDirectoryManager,
    toolI18nService
));
```

**使用静态方法的工具列表**：
- `DatabaseReadTool.getInstance()`
- `DatabaseWriteTool.getInstance()`
- `DatabaseMetadataTool.getInstance()`
- `DatabaseTableToExcelTool.getInstance()`
- `UuidGenerateTool.getInstance()`
- `BrowserUseTool.getInstance()`

---

### 方式 2：直接 new 创建（有状态工具）

**为什么直接 new？**
- 工具有状态，每次需要新实例
- 依赖执行上下文（planId、rootPlanId）

**代码示例**：
```java
// TerminateTool 每次都需要新的实例
toolDefinitions.add(new TerminateTool(
    planId,              // 当前计划 ID
    expectedReturnInfo,  // 期望返回信息
    objectMapper,
    shortUrlService,
    lynxeProperties,
    toolI18nService
));

// FormInputTool 也是每次创建新实例
toolDefinitions.add(new FormInputTool(
    objectMapper,
    toolI18nService
));
```

**需要直接 new 的工具**：
- `TerminateTool` - 终止工具（需要 planId）
- `DebugTool` - 调试工具
- `FileImportOperator` - 文件导入
- `DirectoryOperator` - 目录操作
- `PdfGenerator` - PDF 生成

---

### 方式 3：Spring 注入的 Bean（服务类工具）

**为什么用 Spring？**
- 工具本身就是 Spring 服务
- 需要依赖注入

**代码示例**：
```java
// pptGeneratorOperator 是 @Component
@Autowired
private PptGeneratorOperator pptGeneratorOperator;

// 直接添加
toolDefinitions.add(pptGeneratorOperator);

// 或者通过 ApplicationContext 获取
@SuppressWarnings("unused")
@Autowired
private ApplicationContext applicationContext;
```

**Spring Bean 工具列表**：
- `PptGeneratorOperator` - PPT 生成
- `JsxGeneratorOperator` - JSX 生成
- `ParallelExecutionTool` - 并行执行
- `CronTool` - 定时任务

## 2. 动态工具注册流程

### 2.1 完整流程代码

```java
public Map<String, ToolCallBackContext> toolCallbackMap(
        String planId,
        String rootPlanId,
        String expectedReturnInfo) {

    Map<String, ToolCallBackContext> toolCallbackMap = new HashMap<>();
    List<ToolCallBiFunctionDef<?>> toolDefinitions = new ArrayList<>();

    // ========== 步骤 1：手动创建内置工具 ==========
    if (agentInit) {
        // 静态工厂方法
        toolDefinitions.add(BrowserUseTool.getInstance(...));
        toolDefinitions.add(DatabaseReadTool.getInstance(...));
        toolDefinitions.add(DatabaseWriteTool.getInstance(...));

        // 直接 new
        toolDefinitions.add(new TerminateTool(...));
        toolDefinitions.add(new FormInputTool(...));
        toolDefinitions.add(new DebugTool(...));

        // Spring Bean
        toolDefinitions.add(pptGeneratorOperator);
        toolDefinitions.add(new ParallelExecutionTool(...));
    }

    // ========== 步骤 2：添加 MCP 外部工具 ==========
    List<McpServiceEntity> functionCallbacks =
        mcpService.getFunctionCallbacks(planId);

    for (McpServiceEntity toolCallback : functionCallbacks) {
        String serviceGroup = toolCallback.getServiceGroup();
        ToolCallback[] tCallbacks =
            toolCallback.getAsyncMcpToolCallbackProvider()
                .getToolCallbacks();

        for (ToolCallback tCallback : tCallbacks) {
            toolDefinitions.add(new McpTool(
                tCallback,
                serviceGroup,
                planId,
                innerStorageService,
                objectMapper
            ));
        }
    }

    // ========== 步骤 3：包装为 FunctionToolCallback ==========
    for (ToolCallBiFunctionDef<?> toolDefinition : toolDefinitions) {

        // 设置执行上下文
        toolDefinition.setCurrentPlanId(planId);
        toolDefinition.setRootPlanId(rootPlanId);

        // 处理工具名称（支持服务组）
        String rawToolName = toolDefinition.getName();
        String toolName = ToolNameSanitizer.sanitize(rawToolName);
        String serviceGroup = toolDefinition.getServiceGroup();

        // 构建带索引的名称
        String qualifiedKey;
        if (serviceGroup != null && !serviceGroup.isEmpty()) {
            // database_read_use + serviceGroup index
            Integer index = serviceGroupIndexService
                .getOrAssignIndex(serviceGroup);
            qualifiedKey = toolName + "__" + index;
        } else {
            qualifiedKey = toolName;
        }

        // 创建 Spring AI ToolCallback
        FunctionToolCallback<?, ToolExecuteResult> functionToolcallback =
            FunctionToolCallback.builder(qualifiedKey, toolDefinition)
                .description(toolDefinition.getDescriptionWithServiceGroup())
                .inputSchema(toolDefinition.getParameters())
                .inputType(toolDefinition.getInputType())
                .build();

        // 存储到 Map
        ToolCallBackContext functionToolcallbackContext =
            new ToolCallBackContext(functionToolcallback, toolDefinition);

        toolCallbackMap.put(qualifiedKey, functionToolcallbackContext);
    }

    // ========== 步骤 4：添加子计划工具 ==========
    if (subplanToolService != null) {
        Map<String, ToolCallBackContext> subplanToolCallbacks =
            subplanToolService.createSubplanToolCallbacks(
                planId, rootPlanId, expectedReturnInfo
            );

        // 避免重复注册
        for (Map.Entry<String, ToolCallBackContext> entry : subplanToolCallbacks.entrySet()) {
            toolCallbackMap.putIfAbsent(entry.getKey(), entry.getValue());
        }
    }

    return toolCallbackMap;
}
```

## 3. 工具名称的特殊处理

### 3.1 为什么需要工具名称索引？

**问题场景**：
```
同一个服务组有多个工具：
- database_read_use（主库）
- database_read_use（从库）
- database_read_use（分析库）

LLM 无法区分！
```

**解决方案：添加索引后缀**
```
database_read_use__0  (主库)
database_read_use__1  (从库)
database_read_use__2  (分析库)
```

### 3.2 ServiceGroupIndexService

**作用**：为每个服务组分配索引

```java
// ServiceGroupIndexService 的作用
public Integer getOrAssignIndex(String serviceGroup) {
    // 第一个工具：database-service-group → index = 0
    // 第二个工具：database-service-group → index = 1
    // ...
    return index;
}
```

**完整流程**：
```java
// 1. 获取服务组
String serviceGroup = toolDefinition.getServiceGroup();
// "database-service-group"

// 2. 获取或分配索引
Integer index = serviceGroupIndexService.getOrAssignIndex(serviceGroup);
// 第一次：index = 0
// 第二次：index = 1

// 3. 构建带索引的名称
String qualifiedKey = toolName + "__" + index;
// "database_read_use__0"
```

### 3.3 工具名称清理

**为什么需要清理？**
- LLM 可能生成特殊字符
- 某些字符会被截断

**清理代码**：
```java
String rawToolName = toolDefinition.getName();
// "database_read_use"

String toolName = ToolNameSanitizer.sanitize(rawToolName);
// 清理特殊字符

if (!toolName.equals(rawToolName)) {
    log.warn("Tool name sanitized from '{}' to '{}'",
        rawToolName, toolName);
}
```

## 4. MCP 外部工具集成

### 4.1 什么是 MCP？

**MCP (Model Context Protocol)**：允许 AI 应用连接外部数据源的协议

**作用**：
- 动态加载外部工具
- 不需要修改代码
- 支持第三方服务集成

### 4.2 MCP 工具注册流程

```java
// 获取 MCP 工具列表
List<McpServiceEntity> functionCallbacks =
    mcpService.getFunctionCallbacks(planId);

for (McpServiceEntity toolCallback : functionCallbacks) {
    String serviceGroup = toolCallback.getServiceGroup();
    ToolCallback[] tCallbacks =
        toolCallback.getAsyncMcpToolCallbackProvider()
            .getToolCallbacks();

    // 为每个 MCP 工具创建包装
    for (ToolCallback tCallback : tCallbacks) {
        toolDefinitions.add(new McpTool(
            tCallback,        // Spring AI ToolCallback
            serviceGroup,     // 服务组名称
            planId,           // 计划 ID
            innerStorageService,
            objectMapper
        ));
    }
}
```

**MCP 工具特点**：
- 动态加载
- 不在代码中硬编码
- 可以运行时添加/删除

## 5. 子计划工具

### 5.1 什么是子计划工具？

**子计划工具**：用户定义的可复用流程

**示例**：
```java
// 用户定义的子计划
@SubplanTool(name = "用户数据分析", description = "分析用户行为")
public class UserAnalysisSubplan {
    // 1. 查询用户数据
    // 2. 分析用户行为
    // 3. 生成报告
}
```

### 5.2 子计划工具注册

```java
Map<String, ToolCallBackContext> subplanToolCallbacks =
    subplanToolService.createSubplanToolCallbacks(
        planId,
        rootPlanId,
        expectedReturnInfo,
        serviceGroupIndexService
    );

// 避免与内置工具冲突
for (Map.Entry<String, ToolCallBackContext> entry : subplanToolCallbacks.entrySet()) {
    String baseName = extractBaseToolName(entry.getKey());

    if (existingBaseNames.contains(baseName)) {
        log.warn("Skip registering subplan tool '{}'", entry.getKey());
        continue;
    }

    toolCallbackMap.putIfAbsent(entry.getKey(), entry.getValue());
}
```

## 6. 为什么不用 @Component？

### 6.1 @Component 的问题

| 问题 | 说明 | 影响 |
|------|------|------|
| **全局单例** | 所有请求共享同一实例 | 有状态工具会冲突 |
| **启动注册** | 应用启动时就注册 | 无法动态添加工具 |
| **无法传参** | 构造函数参数固定 | 无法传入 planId |

### 6.2 手动创建的优势

| 优势 | 说明 | 示例 |
|------|------|------|
| **按需创建** | 每次执行时创建 | 可以传入不同的 planId |
| **动态管理** | 运行时添加/删除工具 | MCP 工具、子计划工具 |
| **灵活控制** | 精确控制工具生命周期 | TerminateTool 需要 planId |
| **避免冲突** | 每次都是新实例 | 有状态工具不会互相干扰 |

### 6.3 两种方式对比

```java
// ========== 方式 1：@Component（不适用） ==========
@Component
public class DatabaseReadTool extends AbstractBaseTool<DatabaseRequest> {
    // 问题：无法传入 planId
    // 问题：全局单例，有状态冲突
}

// ========== 方式 2：手动创建（实际使用） ==========
public class DatabaseReadTool extends AbstractBaseTool<DatabaseRequest> {

    public static DatabaseReadToolgetInstance(...) {
        return new DatabaseReadTool(...);
    }

    // 优势：每次执行时创建，可以传入不同的依赖
    // 优势：可以手动管理生命周期
}
```

## 9. 设计亮点总结

### 亮点 1：手动创建优于自动注册 ⭐⭐⭐

**设计**：
- 不使用 @Component 自动扫描
- 使用静态工厂方法手动创建
- 每次执行时动态创建工具实例

**优势**：
- 可以传入执行上下文（planId）
- 避免全局单例的状态冲突
- 支持运行时动态添加工具

---

### 亮点 2：工具名称索引机制 ⭐⭐⭐

**设计**：
- 使用 `serviceGroup + index` 区分同名工具
- `database_read_use__0`、`database_read_use__1`

**优势**：
- 支持多数据源
- 支持工具版本管理
- 避免 LLM 混淆

---

### 亮点 3：三层工具架构 ⭐⭐⭐

**设计**：
```
内置工具 → MCP 工具 → 子计划工具
```

**优势**：
- 内置工具提供核心功能
- MCP 工具支持外部集成
- 子计划工具支持用户自定义

---

### 亮点 4：统一工具抽象 ⭐⭐⭐

**设计**：
- 所有工具实现 `ToolCallBiFunctionDef` 接口
- 统一包装为 `FunctionToolCallback`
- 统一存储到 `toolCallbackMap`

**优势**：
- 接口统一
- 易于扩展
- 易于管理

---

### 亮点 5：服务组管理 ⭐⭐

**设计**：
- `ServiceGroupIndexService` 管理服务组索引
- 自动分配索引号
- 避免索引冲突

**优势**：
- 自动化管理
- 避免手动分配索引
- 支持动态添加工具

## 🎯 学习要点

### 核心概念

1. **手动创建工具**：不使用 @Component，使用静态工厂方法
2. **动态注册**：每次执行时创建并注册工具
3. **工具名称索引**：使用 `__0`、`__1` 区分同名工具
4. **三层架构**：内置工具 + MCP 工具 + 子计划工具
5. **统一抽象**：所有工具实现相同接口

## 💡 总结

### 核心机制

1. **手动创建**：通过静态工厂方法或直接 new 创建工具
2. **动态注册**：每次执行时调用 `toolCallbackMap()` 创建并注册工具
3. **名称索引**：使用 `__0`、`__1` 区分同名工具
4. **三层架构**：内置工具 + MCP 工具 + 子计划工具

### 为什么这样设计？

1. **灵活性**：支持运行时动态添加工具
2. **隔离性**：每次执行都是新实例，避免状态冲突
3. **可扩展性**：MCP 工具 + 子计划工具
4. **可控性**：精确控制工具的生命周期

---

**这个设计是 AgentJ 能够管理 30+ 种工具，并支持动态扩展的核心原因！**
