## 🎯 工具管理的核心问题

### 问题1：为什么不用 @Component 自动扫描？

**常见做法**（Spring Boot）：
```java
@Component  // 自动扫描
public class DatabaseReadTool {
    // Spring 自动注册
}
```

**AgentJ 的做法**（手动创建）：
```java
public class DatabaseReadTool {
    // 没有 @Component
    public static DatabaseReadTool getInstance(...) {
        return new DatabaseReadTool(...);
    }
}

// 在 PlanningFactory 中手动创建
toolDefinitions.add(DatabaseReadTool.getInstance(...));
```

**为什么？**

| 原因 | 说明 | 影响 |
|------|------|------|
| **需要执行上下文** | 工具需要 planId、rootPlanId | @Component 无法动态传入 |
| **避免状态冲突** | 每次执行都是新实例 | 全局单例会导致状态混乱 |
| **动态扩展** | 支持 MCP 工具、子计划工具 | @Component 只能启动时注册 |
| **精确控制** | 手动控制工具生命周期 | 灵活控制何时创建/销毁 |

### 问题2：多个同名工具如何区分？

**场景**：
```
用户配置了3个数据源：
- 主库：serviceGroup = "production_db"
- 从库：serviceGroup = "production_db"  （相同！）
- 分析库：serviceGroup = "analytics_db"

工具名称都是：database_read_use
```

**解决方案**：添加索引后缀
```
database_read_use__0  (主库，production_db 的第0个实例)
database_read_use__1  (从库，production_db 的第1个实例)
database_read_use__0  (分析库，analytics_db 的第0个实例)
```

## 🔧 核心机制1：PlanningFactory 工具注册

### 1.1 完整源码流程

**位置**：`PlanningFactory.java:231-392`

```java
public Map<String, ToolCallBackContext> toolCallbackMap(
        String planId,
        String rootPlanId,
        String expectedReturnInfo) {

    Map<String, ToolCallBackContext> toolCallbackMap = new HashMap<>();
    List<ToolCallBiFunctionDef<?>> toolDefinitions = new ArrayList<>();

    // ========== 第1步：创建内置工具 ==========
    if (agentInit) {
        // 静态工厂方法（无状态工具）
        toolDefinitions.add(BrowserUseTool.getInstance(...));
        toolDefinitions.add(DatabaseReadTool.getInstance(...));
        toolDefinitions.add(DatabaseWriteTool.getInstance(...));
        toolDefinitions.add(DatabaseMetadataTool.getInstance(...));
        toolDefinitions.add(DatabaseTableToExcelTool.getInstance(...));
        toolDefinitions.add(UuidGenerateTool.getInstance(...));

        // 直接 new（有状态工具）
        toolDefinitions.add(new TerminateTool(planId, expectedReturnInfo, ...));
        toolDefinitions.add(new DebugTool(...));
        toolDefinitions.add(new FileImportOperator(...));
        toolDefinitions.add(new DirectoryOperator(...));
        toolDefinitions.add(new PdfGenerator());

        // Spring Bean（本身就是 Spring 服务）
        toolDefinitions.add(pptGeneratorOperator);
        toolDefinitions.add(new ParallelExecutionTool(...));
        toolDefinitions.add(new CronTool(...));
        toolDefinitions.add(new MarkdownConverterTool(...));
    }

    // ========== 第2步：添加 MCP 外部工具 ==========
    List<McpServiceEntity> functionCallbacks =
        mcpService.getFunctionCallbacks(planId);

    for (McpServiceEntity toolCallback : functionCallbacks) {
        String serviceGroup = toolCallback.getServiceGroup();
        ToolCallback[] tCallbacks =
            toolCallback.getAsyncMcpToolCallbackProvider()
                .getToolCallbacks();

        for (ToolCallback tCallback : tCallbacks) {
            toolDefinitions.add(new McpTool(
                tCallback,
                serviceGroup,
                planId,
                innerStorageService,
                objectMapper
            ));
        }
    }

    // ========== 第3步：包装为 FunctionToolCallback ==========
    for (ToolCallBiFunctionDef<?> toolDefinition : toolDefinitions) {

        // 3.1 设置执行上下文
        toolDefinition.setCurrentPlanId(planId);
        toolDefinition.setRootPlanId(rootPlanId);

        // 3.2 清理工具名称
        String rawToolName = toolDefinition.getName();
        String toolName = ToolNameSanitizer.sanitize(rawToolName);

        // 3.3 构建带索引的名称
        String serviceGroup = toolDefinition.getServiceGroup();
        String qualifiedKey;

        if (serviceGroup != null && !serviceGroup.isEmpty()) {
            Integer index = serviceGroupIndexService
                .getOrAssignIndex(serviceGroup);
            if (index != null) {
                qualifiedKey = toolName + "__" + index;  // 关键！
            } else {
                qualifiedKey = toolName;
            }
        } else {
            qualifiedKey = toolName;
        }

        // 3.4 创建 Spring AI ToolCallback
        FunctionToolCallback<?, ToolExecuteResult> functionToolcallback =
            FunctionToolCallback.builder(qualifiedKey, toolDefinition)
                .description(toolDefinition.getDescriptionWithServiceGroup())
                .inputSchema(toolDefinition.getParameters())
                .inputType(toolDefinition.getInputType())
                .toolMetadata(ToolMetadata.builder()
                    .returnDirect(toolDefinition.isReturnDirect())
                    .build())
                .build();

        // 3.5 存储到 Map
        ToolCallBackContext context = new ToolCallBackContext(
            functionToolcallback,
            toolDefinition
        );

        toolCallbackMap.put(qualifiedKey, context);
    }

    // ========== 第4步：添加子计划工具 ==========
    if (subplanToolService != null) {
        // 收集已存在的基础名称
        Set<String> existingBaseNames = new HashSet<>();
        for (String existingKey : toolCallbackMap.keySet()) {
            existingBaseNames.add(extractBaseToolName(existingKey));
        }

        Map<String, ToolCallBackContext> subplanToolCallbacks =
            subplanToolService.createSubplanToolCallbacks(
                planId, rootPlanId, expectedReturnInfo, serviceGroupIndexService
            );

        // 避免重复注册
        for (Map.Entry<String, ToolCallBackContext> entry :
             subplanToolCallbacks.entrySet()) {
            String baseName = extractBaseToolName(entry.getKey());

            if (existingBaseNames.contains(baseName)) {
                log.warn("Skip registering subplan tool '{}' " +
                         "because base name '{}' already exists",
                         entry.getKey(), baseName);
                continue;  // 跳过重复的工具
            }

            toolCallbackMap.putIfAbsent(entry.getKey(), entry.getValue());
        }
    }

    return toolCallbackMap;
}
```

## 🔧 核心机制2：ServiceGroupIndexService

### 2.1 索引分配逻辑

```java
public class ServiceGroupIndexService {

    // 存储服务组 → 索引的映射
    private final Map<String, AtomicInteger> groupIndexMap = new ConcurrentHashMap<>();

    public Integer getOrAssignIndex(String serviceGroup) {
        return groupIndexMap.computeIfAbsent(serviceGroup,
            key -> new AtomicInteger(0)
        ).getAndIncrement();
    }
}
```

**执行流程**：

```
第1个工具：serviceGroup = "production_db"
    ↓
groupIndexMap.computeIfAbsent("production_db", ...)
    → map.put("production_db", new AtomicInteger(0))
    → 返回 0
    → getAndIncrement() → 内部值变为 1
    ↓
工具名称：database_read_use__0

第2个工具：serviceGroup = "production_db" (相同)
    ↓
groupIndexMap.computeIfAbsent("production_db", ...)
    → 已存在，不创建新的 AtomicInteger
    → 返回 1
    → getAndIncrement() → 内部值变为 2
    ↓
工具名称：database_read_use__1

第3个工具：serviceGroup = "analytics_db" (不同)
    ↓
groupIndexMap.computeIfAbsent("analytics_db", ...)
    → map.put("analytics_db", new AtomicInteger(0))
    → 返回 0 (重新开始计数！)
    ↓
工具名称：database_read_use__0
```

### 2.2 索引分配示例

**场景**：配置了多个数据源

```java
// PlanningFactory.toolCallbackMap() 中的代码
toolDefinitions.add(DatabaseReadTool.getInstance(
    "primary_db"      // serviceGroup
));
toolDefinitions.add(DatabaseReadTool.getInstance(
    "replica_db"      // serviceGroup
));
toolDefinitions.add(DatabaseReadTool.getInstance(
    "analytics_db"    // serviceGroup
));
toolDefinitions.add(DatabaseWriteTool.getInstance(
    "primary_db"      // serviceGroup (与第1个相同！)
));
```

**执行结果**：

```
工具1：DatabaseReadTool (serviceGroup = "primary_db")
  → index = 0
  → qualifiedKey = "database_read_use__0"

工具2：DatabaseReadTool (serviceGroup = "replica_db")
  → index = 0 (新的服务组，重新计数)
  → qualifiedKey = "database_read_use__0"

工具3：DatabaseReadTool (serviceGroup = "analytics_db")
  → index = 0 (新的服务组，重新计数)
  → qualifiedKey = "database_read_use__0"

工具4：DatabaseWriteTool (serviceGroup = "primary_db")
  → index = 1 (继续 primary_db 的计数)
  → qualifiedKey = "database_write_use__1"
```

### 2.3 索引的存储和生命周期

```java
// ServiceGroupIndexService 的字段
private final Map<String, AtomicInteger> groupIndexMap = new ConcurrentHashMap<>();
```

**特点**：
1. **全局单例**：整个应用共享一个 ServiceGroupIndexService
2. **持续递增**：索引只增不减
3. **跨请求共享**：不同的 AI 请求共享索引分配

**问题**：索引会无限增长吗？

**答案**：不会，因为：
- 实际使用中，serviceGroup 数量有限（数据源配置）
- 索引只是短整型（Integer），最多 2^31-1 个
- 即使达到上限，也可以通过重启应用重置

## 🔧 核心机制3：ToolNameSanitizer

### 3.1 为什么要清理工具名称？

**问题场景**：
```
LLM 生成工具名称时可能包含特殊字符：
- database_read_use*    (* 是特殊字符)
- bash#command          (# 是特殊字符)
- browser@action        (@ 是特殊字符)

这些字符可能：
1. 被 LLM 截断
2. 导致工具调用失败
3. 与系统保留字冲突
```

### 3.2 清理逻辑

**位置**：`PlanningFactory.java:312-316`

```java
String rawToolName = toolDefinition.getName();
// 例如："database_read_use*"

String toolName = ToolNameSanitizer.sanitize(rawToolName);
// 清理后："database_read_use"

if (!toolName.equals(rawToolName)) {
    log.warn("Tool name sanitized from '{}' to '{}' " +
             "to satisfy provider constraints",
             rawToolName, toolName);
}
```

**清理规则**（推测）：
```java
public class ToolNameSanitizer {
    public static String sanitize(String toolName) {
        if (toolName == null) {
            return null;
        }

        // 移除特殊字符
        String cleaned = toolName
            .replaceAll("[^a-zA-Z0-9_]", "");  // 只保留字母、数字、下划线
            .replaceAll("_{2,}", "_");          // 多个下划线合并为一个

        return cleaned;
    }
}
```

### 3.3 清理示例

| 原始名称 | 清理后 | 原因 |
|---------|--------|------|
| `database_read_use*` | `database_read_use` | 移除 `*` |
| `bash#command` | `bashcommand` | 移除 `#` |
| `browser@action` | `browseraction` | 移除 `@` |
| `tool__name` | `tool_name` | 合并多个下划线 |
| `valid_tool_name` | `valid_tool_name` | 无需清理 |

## 🔧 核心机制4：子计划工具去重

### 4.1 为什么需要去重？

**场景**：
```
内置工具：database_read_use__0
子计划工具：database_read_use__5 (用户定义的)

如果都注册，LLM 会看到：
- database_read_use__0 (内置)
- database_read_use__5 (子计划)

LLM 会混淆：不知道该调用哪个！
```

### 4.2 去重逻辑

**位置**：`PlanningFactory.java:359-383`

```java
// 收集已存在的基础名称
Set<String> existingBaseNames = new HashSet<>();
for (String existingKey : toolCallbackMap.keySet()) {
    existingBaseNames.add(extractBaseToolName(existingKey));
    // 例如：
    // "database_read_use__0" → "database_read_use"
    // "bash" → "bash"
}

// 检查子计划工具是否冲突
for (Map.Entry<String, ToolCallBackContext> entry :
     subplanToolCallbacks.entrySet()) {

    String baseName = extractBaseToolName(entry.getKey());
    // 例如：extractBaseToolName("database_read_use__5")
    //      → "database_read_use"

    if (existingBaseNames.contains(baseName)) {
        log.warn("Skip registering subplan tool '{}' " +
                 "because base name '{}' already exists in registry",
                 entry.getKey(), baseName);
        continue;  // 跳过，保留内置工具
    }

    toolCallbackMap.putIfAbsent(entry.getKey(), entry.getValue());
}
```

### 4.3 extractBaseToolName() 方法

**位置**：`PlanningFactory.java:425-432`

```java
private String extractBaseToolName(String qualifiedKey) {
    if (qualifiedKey == null) {
        return null;
    }

    int idx = qualifiedKey.indexOf("__");
    if (idx > 0) {
        return qualifiedKey.substring(0, idx);
    }

    return qualifiedKey;
}
```

**示例**：
```java
extractBaseToolName("database_read_use__0")
  → "database_read_use"

extractBaseToolName("database_read_use__5")
  → "database_read_use"

extractBaseToolName("bash")
  → "bash"

extractBaseToolName("browser_use__2")
  → "browser_use"
```

### 4.4 去重流程图

```
子计划工具注册
    ↓
收集已存在的基础名称
    ↓
┌──────────────────────────────────────┐
│ 遍历子计划工具                         │
├──────────────────────────────────────┤
│ entry.getKey() = "database_read_use__5"│
│ ↓                                     │
│ extractBaseToolName(key)              │
│ → "database_read_use"                 │
└──────────────────────────────────────┘
    ↓
┌──────────────────────────────────────┐
│ 检查是否冲突                           │
├──────────────────────────────────────┤
│ existingBaseNames.contains(           │
│   "database_read_use") ?              │
│                                       │
│ YES → 跳过注册，保留内置工具            │
│ NO  → 注册子计划工具                   │
└──────────────────────────────────────┘
```

## 🔧 核心机制5：工具注册的优先级

### 5.1 注册顺序

```java
// 第1步：内置工具（优先级最高）
if (agentInit) {
    toolDefinitions.add(BrowserUseTool.getInstance(...));
    toolDefinitions.add(DatabaseReadTool.getInstance(...));
    // ... 30+ 个内置工具
}

// 第2步：MCP 工具（动态加载）
for (McpServiceEntity toolCallback : functionCallbacks) {
    toolDefinitions.add(new McpTool(...));
}

// 第3步：子计划工具（优先级最低）
for (Map.Entry<String, ToolCallBackContext> entry :
     subplanToolCallbacks.entrySet()) {
    toolCallbackMap.putIfAbsent(entry.getKey(), entry.getValue());
    // ↑ 注意：使用 putIfAbsent，不会覆盖已存在的工具
}
```

### 5.2 优先级规则

| 工具类型 | 优先级 | 冲突时 | 原因 |
|---------|-------|--------|------|
| **内置工具** | ⭐⭐⭐ 最高 | 保留 | 核心功能，稳定性优先 |
| **MCP 工具** | ⭐⭐ 中等 | 可能被覆盖 | 动态加载，灵活性优先 |
| **子计划工具** | ⭐ 最低 | 跳过注册 | 用户自定义，避免冲突 |

### 5.3 putIfAbsent 的作用

```java
// 不会覆盖已存在的工具
toolCallbackMap.putIfAbsent(key, value);

// 等价于：
if (!toolCallbackMap.containsKey(key)) {
    toolCallbackMap.put(key, value);
}
```

**为什么用 putIfAbsent？**
- 保证内置工具优先
- 避免 MCP 工具覆盖内置工具
- 避免子计划工具覆盖内置/MCP 工具

## 📝 今日总结

### 核心概念

1. **手动创建工具**：不使用 @Component，使用静态工厂方法
