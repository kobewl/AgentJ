## 🎯 工具系统概览

### 1.1 工具是什么？

在 AgentJ 智能体中，**工具（Tool）**是智能体执行具体任务的能力单元：

```
智能体 = 大脑（LLM）+ 工具（手脚）

LLM: "我需要查询北京天气"
    ↓
智能体分析：需要调用天气API
    ↓
调用 weatherQuery 工具
    ↓
返回结果给用户
```

### 1.2 工具系统的分层架构

```
┌─────────────────────────────────┐
│ 接口层                             │
│ - ToolCallBiFunctionDef           │ ← 定义工具的标准接口
│ - TerminableTool                 │ ← 定义可终止工具接口
└─────────────────────────────────┘
              ↓
┌─────────────────────────────────┐
│ 基类层                             │
│ - AbstractBaseTool                │ ← 提供通用实现
│ - 管理计划ID、工具状态等           │
└─────────────────────────────────┘
              ↓
┌─────────────────────────────────┐
│ 实现层                             │
│ - Bash                             │ ← 命令执行工具
│ - DatabaseRead/Write              │ ← 数据库操作
│ - BrowserUseTool                  │ ← 浏览器自动化
│ - FormInputTool                   │ ← 表单输入
│ - ... (30+ 种工具)                │
└─────────────────────────────────┘
              ↓
┌─────────────────────────────────┐
│ 管理层                             │
│ - PlanningFactory                  │ ← 工具注册和管理
│ - ToolI18nService                 │ ← 国际化支持
│ - ToolCallingManager               │ ← 工具调用执行
└─────────────────────────────────┘
```

## 🔑 核心接口：ToolCallBiFunctionDef

### 1.1 接口定义

**位置**：`tools/ToolCallBiFunctionDef.java`

```java
public interface ToolCallBiFunctionDef<I> extends BiFunction<I, ToolContext, ToolExecuteResult> {

    // ========== 基本信息 ==========

    /**
     * 获取工具的服务组名
     * 用于工具分组管理，不同组的工具可以有相同的名称
     */
    String getServiceGroup();

    /**
     * 获取工具名称（全局唯一）
     */
    String getName();

    /**
     * 获取工具描述
     * 用于告诉 LLM 这个工具的功能
     */
    String getDescription();

    /**
     * 获取工具描述（带服务组后缀）
     */
    String getDescriptionWithServiceGroup();

    // ========== 参数定义 ==========

    /**
     * 获取参数定义的 JSON Schema
     * 用于告诉 LLM 如何调用这个工具
     */
    String getParameters();

    /**
     * 获取输入参数类型
     * Spring AI 使用这个类型来反序列化参数
     */
    Class<I> getInputType();

    // ========== 执行控制 ==========

    /**
     * 判断工具是否直接返回结果
     * true: 返回工具执行的原始输出
     * false: 返回处理后的结果
     */
    boolean isReturnDirect();

    /**
     * 判断工具是否可被选择
     * 用于动态过滤工具
     */
    boolean isSelectable();

    // ========== 计划管理 ==========

    /**
     * 设置当前计划ID
     * 用于标识当前执行上下文
     */
    void setCurrentPlanId(String planId);

    /**
     * 设置根计划ID
     * 用于多层级执行
     */
    void setRootPlanId(String rootPlanId);

    // ========== 状态管理 ==========

    /**
     * 获取工具当前状态字符串
     * 用于将工具状态注入到 Prompt 中
     */
    String getCurrentToolStateString();

    /**
     * 清理工具资源
     * 在执行完成后调用
     */
    void cleanup(String planId);
}
```

### 1.2 接口设计要点

#### 要点 1：泛型设计

```java
public interface ToolCallBiFunctionDef<I> extends BiFunction<I, ToolContext, ToolExecuteResult>
```

- **I**: 输入参数类型（如 `BashInput`, `DatabaseRequest`）
- **ToolContext**: 工具执行上下文
- **ToolExecuteResult**: 工具执行结果

**为什么使用泛型？**
- 类型安全：编译时检查参数类型
- 灵活性：每个工具定义自己的输入类型

#### 要点 2：继承 BiFunction

```java
extends BiFunction<I, ToolContext, ToolExecuteResult>
```

- **apply(input, context) → result**
- 兼容 Java 函数式接口
- 可以用 Lambda 表达式实现

#### 要点 3：服务组管理

```java
String getServiceGroup();  // 例如 "database-service-group"
String getName();           // 例如 "database_read_use"
```

**作用**：
- 支持工具分组
- 允许不同组有同名工具
- 便于工具管理和权限控制

## 🏗️ 工具基类：AbstractBaseTool

### 2.1 基类结构

**位置**：`tools/AbstractBaseTool.java`

```java
public abstract class AbstractBaseTool<I> implements ToolCallBiFunctionDef<I> {

    // ========== 依赖服务 ==========
    protected LynxeProperties lynxeProperties;
    protected ToolI18nService toolI18nService;
    protected ObjectMapper objectMapper;

    // ========== 计划管理 ==========
    protected String currentPlanId;
    protected String rootPlanId;

    // ========== 工具信息 ==========
    private final String name;
    private final String serviceGroup;

    // ========== 核心方法 ==========

    /**
     * 工具执行方法（子类实现）
     */
    public abstract ToolExecuteResult run(I input) throws Exception;

    /**
     * 获取工具名称
     */
    @Override
    public String getName() {
        return name;
    }

    /**
     * 获取工具描述
     * 从 i18n 服务读取，支持多语言
     */
    @Override
    public String getDescription() {
        return toolI18nService.getDescription(getName());
    }

    /**
     * 获取参数定义
     * 从 i18n 服务读取 JSON Schema
     */
    @Override
    public String getParameters() {
        return toolI18nService.getParameters(getName());
    }

    // ========== 计划ID管理 ==========

    @Override
    public void setCurrentPlanId(String planId) {
        this.currentPlanId = planId;
    }

    @Override
    public String getCurrentPlanId() {
        return currentPlanId;
    }

    @Override
    public void setRootPlanId(String rootPlanId) {
        this.rootPlanId = rootPlanId;
    }

    @Override
    public String getRootPlanId() {
        return rootPlanId;
    }

    // ========== 其他方法 ==========

    @Override
    public String getServiceGroup() {
        return serviceGroup;
    }

    @Override
    public Class<I> getInputType() {
        // 通过反射获取
        ParameterizedType parameterizedType =
            new ParameterizedType(getClass(), AbstractBaseTool.class);
        return (Class<I>) parameterizedType.getActualTypeArguments()[0];
    }

    @Override
    public boolean isReturnDirect() {
        return true;
    }

    @Override
    public boolean isSelectable() {
        return true;
    }

    @Override
    public String getCurrentToolStateString() {
        return "";  // 子类可以覆盖
    }

    @Override
    public void cleanup(String planId) {
        // 默认不做任何清理，子类可以覆盖
    }

    // BiFunction 接口实现
    @Override
    public ToolExecuteResult apply(I input, ToolContext context) {
        try {
            return run(input);
        } catch (Exception e) {
            log.error("Tool execution failed", e);
            return new ToolExecuteResult("Tool execution failed: " + e.getMessage());
        }
    }
}
```

### 2.2 基类提供的功能

| 功能 | 说明 | 代码位置 |
|------|------|----------|
| **计划ID管理** | 管理 currentPlanId 和 rootPlanId | 字段 + getter/setter |
| **工具信息获取** | 从 i18n 服务读取名称、描述、参数 | getDescription() 等 |
| **异常处理** | 统一的异常包装和日志记录 | apply() 方法 |
| **类型反射** | 自动推断泛型参数类型 | getInputType() |
| **状态管理** | 提供状态字符串接口 | getCurrentToolStateString() |

## 🎯 工具的生命周期

### 3.1 完整生命周期

```
1. 注册阶段
   └─ PlanningFactory 扫描 @Component
   └─ 创建 ToolCallBackContext
   └─ 注册到 ToolCallbackProvider

2. 初始化阶段
   └─ DynamicAgent 调用 getToolCallBackContext()
   └─ 获取工具实例
   └─ 设置 currentPlanId 和 rootPlanId

3. 执行阶段
   ├─ DynamicAgent.think() 调用 collectEnvData()
   │   └─ 调用 getCurrentToolStateString()
   ├─ DynamicAgent.act() 选择工具
   ├─ 构建工具参数
   └─ 调用 apply(input, context)

4. 清理阶段
   └─ DynamicAgent.clearUp() 调用 cleanup()
   └─ 释放资源（如关闭浏览器连接）
```

### 3.2 代码示例

**注册**（自动通过 Spring）：
```java
@Component
public class Bash extends AbstractBaseTool<Bash.BashInput> {
    // Spring 自动扫描并注册
}
```

**使用**：
```java
// DynamicAgent 中
String toolKey = "bash";  // 或者 "database_read_use"
PlanningFactory.ToolCallBackContext context =
    toolCallbackProvider.getToolCallBackContext(toolKey);
ToolCallBiFunctionDef<?> tool = context.getFunctionInstance();

// 设置计划ID
tool.setCurrentPlanId(currentPlanId);

// 执行工具
ToolExecuteResult result = tool.apply(input, context);
```

## 💡 关键设计模式

### 模式 1：模板方法模式

```java
AbstractBaseTool 定义算法骨架：
├─ getDescription()  - 从 i18n 读取
├─ getParameters()   - 从 i18n 读取
└─ run()           - 子类实现具体逻辑
```

**优势**：
- 统一的工具信息管理
- 支持多语言
- 减少重复代码

### 模式 2：依赖注入

```java
@Component
public class Bash extends AbstractBaseTool<BashInput> {

    private final UnifiedDirectoryManager directoryManager;

    // 构造函数注入
    public Bash(UnifiedDirectoryManager directoryManager,
               ObjectMapper objectMapper) {
        this.directoryManager = directoryManager;
        this.objectMapper = objectMapper;
    }
}
```

**优势**：
- 松耦合
- 易于测试
- 便于替换依赖

### 模式 3：策略模式

```java
ToolCallBiFunctionDef<I> 是一个策略接口：
├─ 不同的工具实现不同的执行策略
├─ DynamicAgent 根据情况选择工具
└─ 统一的调用接口 apply()
```
