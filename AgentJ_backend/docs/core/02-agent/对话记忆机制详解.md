## 概述

AgentJ 系统采用**双层记忆架构**来管理对话历史：

| 记忆类型 | 作用域 | 存储位置 | 生命周期 | 用途 |
|---------|--------|---------|----------|------|
| **Agent 记忆** | `planId` | 内存 | 服务重启丢失 | 单次执行过程的工具调用历史 |
| **会话记忆** | `conversationId` | 数据库 | 持久化 | 跨轮次对话上下文 |

## 双层记忆架构

### 1. Agent 记忆（短期记忆）

**存储位置**: 内存 (`InMemoryChatMemoryRepository`)

**代码位置**: `LlmService.java:196-205`

```java
public ChatMemory getAgentMemory(Integer maxMessages) {
    if (agentMemory == null) {
        agentMemory = MessageWindowChatMemory.builder()
            .chatMemoryRepository(new InMemoryChatMemoryRepository())  // 内存存储
            .maxMessages(maxMessages)
            .build();
    }
    return agentMemory;
}
```

**特点**:
- ✅ 高性能读写
- ❌ 服务重启后丢失
- 📝 用于存储当前 `planId` 执行过程中的：
  - LLM 对话历史
  - 工具调用记录
  - 思考-行动循环结果

**保存时机**: `DynamicAgent.java:1293-1317`

```java
private void processMemory(ToolExecutionResult toolExecutionResult) {
    // 清空当前 plan 内存
    llmService.getAgentMemory(lynxeProperties.getMaxMemory()).clear(getCurrentPlanId());

    // 只保留 assistant 和 tool_call 消息
    for (Message message : messages) {
        if (!(message instanceof SystemMessage) && !(message instanceof UserMessage)) {
            llmService.getAgentMemory(...).add(getCurrentPlanId(), message);
        }
    }
}
```

### 2. 会话记忆（长期记忆）

**存储位置**: 数据库 (`ai_chat_memory` 表)

**代码位置**: `LlmService.java:237-245`

```java
public ChatMemory getConversationMemory(Integer maxMessages) {
    if (conversationMemory == null) {
        conversationMemory = MessageWindowChatMemory.builder()
            .chatMemoryRepository(chatMemoryRepository)  // 数据库存储
            .maxMessages(maxMessages)
            .build();
    }
    return conversationMemory;
}
```

**支持数据库**:
- **MySQL** (`MysqlChatMemoryRepository`)
- **PostgreSQL** (`PostgresChatMemoryRepository`)
- **H2** (`H2ChatMemoryRepository`)

**表结构** (`MysqlChatMemoryRepository.java:62-68`):

```sql
CREATE TABLE ai_chat_memory (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    conversation_id VARCHAR(256) NOT NULL,        -- 会话 ID
    user_id BIGINT NULL,                          -- 用户 ID
    content LONGTEXT NOT NULL,                    -- 消息内容
    type VARCHAR(100) NOT NULL,                   -- 消息类型: USER/ASSISTANT/SYSTEM/TOOL
    timestamp TIMESTAMP NOT NULL,                 -- 时间戳
    CONSTRAINT fk_ai_chat_memory_user FOREIGN KEY (user_id) REFERENCES users(id)
);
```

**保存时机**: `DynamicAgent.java:1503-1546`

## 对话上下文构建

### 完整的消息构建流程

**代码位置**: `DynamicAgent.java:254-287`

```java
List<Message> messages = new ArrayList<>();

// 1️⃣ 会话历史（跨轮次）- 从数据库加载
if (lynxeProperties.getEnableConversationMemory() && memoryService != null
        && getConversationId() != null && !getConversationId().trim().isEmpty()) {
    ChatMemory conversationMemory = llmService
        .getConversationMemoryWithLimit(lynxeProperties.getMaxMemory(), getConversationId());
    List<Message> conversationHistory = conversationMemory.get(getConversationId());
    if (conversationHistory != null && !conversationHistory.isEmpty()) {
        messages.addAll(conversationHistory);  // 跨轮次对话历史
    }
}

// 2️⃣ 系统消息
messages.addAll(Collections.singletonList(systemMessage));

// 3️⃣ Agent 内部记忆（当前 plan）- 从内存加载
ChatMemory chatMemory = llmService.getAgentMemory(lynxeProperties.getMaxMemory());
List<Message> historyMem = chatMemory.get(getCurrentPlanId());
messages.addAll(historyMem);

// 4️⃣ 当前环境数据
messages.add(currentStepEnvMessage);

// 5️⃣ 保存用户请求到会话记忆
saveUserRequestToConversationMemory();
```

### 消息优先级顺序

```
┌─────────────────────────────────────────────────────┐
│ 1. 会话历史（conversationId）- 跨轮次长期上下文      │
├─────────────────────────────────────────────────────┤
│ 2. 系统消息 - Agent 角色和规则                       │
├─────────────────────────────────────────────────────┤
│ 3. Agent 历史（planId）- 当前执行短期上下文          │
├─────────────────────────────────────────────────────┤
│ 4. 当前环境数据 - 工具状态、变量等                   │
└─────────────────────────────────────────────────────┘
```

## 配置与使用

### 1. 配置文件

**application.yml**:

```yaml
lynxe:
  enable-conversation-memory: true
  max-memory: 100              # 最大消息数量
```

### 2. 前端使用（重要 ⚠️）

**问题**: 如果前端不传递 `conversationId`，每次对话都是新的会话。

**正确用法**:

```typescript
// ✅ 第一次对话 - 不传 conversationId，后端生成新的
const response1 = await executeByToolAsync({
  toolName: 'auto_general_exec',
  replacementParams: { task: '帮我查询天气' }
  // conversationId: undefined  // 第一次不传
});

// 保存返回的 conversationId
const conversationId = response1.data.conversationId;

// ✅ 第二次对话 - 传递同一个 conversationId
const response2 = await executeByToolAsync({
  toolName: 'auto_general_exec',
  replacementParams: { task: '明天呢？' },
  conversationId: conversationId  // 复用同一个会话 ID
});
```

**错误用法**:

```typescript
// ❌ 每次都不传 conversationId，导致无法连续对话
await executeByToolAsync({
  toolName: 'auto_general_exec',
  replacementParams: { task: '第一轮对话' }
  // conversationId: undefined
});

await executeByToolAsync({
  toolName: 'auto_general_exec',
  replacementParams: { task: '第二轮对话' }
  // conversationId: undefined  // 又是新会话！
});
```

## 常见问题

### Q1: 为什么前端只能对话一次？

**原因**: 前端没有保存和传递 `conversationId`。

**解决**: 参考上文的"前端使用"部分。

### Q2: Agent 记忆和会话记忆有什么区别？

| 维度 | Agent 记忆 | 会话记忆 |
|-----|-----------|----------|
| 作用域 | `planId` | `conversationId` |
| 存储 | 内存 | 数据库 |
| 生命周期 | 服务重启丢失 | 持久化 |
| 内容 | 工具调用细节 | 用户对话历史 |
| 用途 | 单次执行连贯性 | 跨轮次上下文 |

### Q3: 如何清空对话历史？

```java
// 清空 Agent 记忆
llmService.clearAgentMemory(planId);

// 清空会话记忆
llmService.clearConversationMemory(conversationId);
```
